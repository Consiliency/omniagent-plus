## Cross-Cutting Findings

| ID | Source-supported finding | Decision impact and missing proof |
| --- | --- | --- |
| F1: affinity is not identity authority | Routing offers round-robin, weighted round-robin and fill-first; affinity defaults off with a one-hour configured TTL. Configuration explicitly allows failover when the bound auth becomes unavailable; selector result handling releases credential-attributed failing bindings. [Config][config], [selector][selector] | A selected account may change after failure, cache expiry or restart. Cannot equate sticky routing with durable session identity. Require an isolated single-credential endpoint or independently proven hard pin; do not assume internal Go metadata pinning is an authenticated HTTP identity contract |
| F2: quota policy mismatch | Retry rounds and per-credential limits exist; `request-retry: 3`, `max-retry-credentials: 0` in the example. Zero additional rounds does **not** prohibit trying other credentials in initial round zero. Cooldown overrides can disable cooling; Home mode owns a separate policy. [Execution][execution], [cooldown][cooldown], [config][config] | Retain our limit classifier, family cooldown and explicit policy gates. A hard cap/unknown limit must not silently become another-account work. Quota signals and usage estimates are not an authoritative remaining-entitlement oracle |
| F3: refresh is a second credential writer | Auto-refresh scheduler, per-auth refresh locks and `UpdateRefreshedAuth` persistence paths exist. Provider auth code has refresh handling. [Refresh manager][refresh-manager] | Process-local locks do not prove coordination with native CLI writers or GCP pool reconciliation. Never point proxy storage at native auth files, import a live shared refresh lineage, or let both own the same rotation transaction. Revocation, concurrent refresh, persistence failure and restart remain untested |
| F4: retry safety is narrower than exactly-once work | Stream bootstrap handles errors before first payload; the wrapper forwards subsequent chunks/errors. Retry loops can select another credential before delivery. Optional Codex bootstrap buffering can extend the pre-delivery retry window. [Stream conductor][stream], [execution][execution], [config][config] | No end-to-end exactly-once proof. No downstream bytes does not establish that upstream work never occurred. Drop-after-acceptance can replay billed work or provider-hosted tools. Disable implicit retries for ambiguous/non-idempotent operations and settle unknown outcomes explicitly |
| F5: tool support is translation, not execution parity | Codex-to-Claude translator maps function calls and incremental arguments into tool-use events, including call-ID sanitization/shortening. Terminal/bootstrap test sources exist. [Tool translation][tools], [Claude terminal tests][terminal-tests], [Codex bootstrap tests][bootstrap-tests] | Test fragmented/multiple calls, ID round trips, tool results, cancellation and terminal uniqueness on the exact selected format. Keep tool approval/execution/deduplication in the harness. Do not claim provider-hosted tools are equivalent or safe to replay |
| F6: default exposure is unsuitable | Example host is empty (all interfaces), TLS off. Management is locally restricted with a required key when enabled; empty management secret disables routes, but `MANAGEMENT_PASSWORD` enables a remote override. Client API keys and management auth are separate controls. [Config][config], [management][management], [client auth][client-auth] | Explicit loopback bind, scrubbed environment, private auth directory, client authentication, management disabled, panel download disabled. Loopback does not isolate other users on a team host; require a private OS/network boundary. Test remote and cross-user denial, not just local success |
| F7: redaction is not metadata-only | Sensitive header/query masking exists, but request bodies are retained in logging paths; error-only response writer can force logging when request logging is disabled. [Logging helpers][logging], [error logging][error-logging], [masking][masking] | Full-body/error/cookie/custom-field leakage needs sentinel tests. Disable debug/body capture and exclude control-plane collectors; `request-log: false` alone is insufficient proof. Export only allowlisted event fields, never raw bodies, tokens, account email or auth-file names |
| F8: session/control-plane mismatch | No native-process adoption or Claude Remote Control rebind implementation was identified in the inspected upstream docs/sdk/internal paths. Anthropic's current Remote Control docs explicitly reject non-Anthropic `ANTHROPIC_BASE_URL`, even with subscription login. [Remote Control][remote-control] | Existing process environment cannot be retroactively changed by starting a proxy. A proxy-started CLI is a different experiment, not proof of seamless adoption. Full replacement cannot pass the current Remote Control requirement on this documented route |

Observability building blocks include selected-auth metadata, per-result identity/model attribution and request logging ([execution][execution], [stream][stream]). They are not our durable route ledger, account authorization boundary, or replay-safe audit contract. Usage counters alone cannot prove account charging. Cluster/Home mode, extra usage dashboards, remote management, plugins and auto-updates are excluded from the smallest experiment.
