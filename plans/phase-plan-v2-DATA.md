# DATA: Content and durable state

## Context

Phase 3 follows the merged GUARD gate in omniagent-plus#29. Related issues are omniagent-plus#21 and omniagent-plus#22. COORD and WIRE consume DATA's interfaces. The current scanner truncates any invalid last line, including complete schema-invalid JSON; replay silently stops at an invalid last line. Append also rescans the ledger and rebuilds indexes. Repair invalid-tail classification before tightening content validation. Do not edit the external canon package or dispatch a release.

## Resolved execution contracts

- The private state-ledger backend and root workspace require Node `^22.13.0 || >=24.0.0`, including built-in `node:sqlite` without flags. Published runtime-provider and transport contracts retain their existing platform support. JSONL remains the record backend; SQLite arbitrates writers only, on one host/PID namespace and a local filesystem supporting SQLite locks, hard links, atomic same-directory rename, and file/directory fsync. Unsupported durability topology fails explicitly rather than claiming power-loss proof.
- `withFilesystemLock` uses a permanent, versioned SQLite arbitration file. Initialize a temporary database containing its schema and random instance identity; close and fsync it fully before exclusively hard-linking it to the contested path and syncing the parent. Canonical arbitration files are never deleted by owners. A SQLite transaction provides atomic process ownership and crash release. Legacy or unprovable files block writers and remain available for inspection. Never raw-open/close the published SQLite inode: unrelated POSIX closes can cancel SQLite locks. Validate identity through SQL and pathname metadata. A replacement inode fails the operation and is left intact. Supported writers are cooperative and do not remove/replace an active arbitration inode; metadata checks cannot fence arbitrary external tampering during a callback. Use rollback-journal mode, immutable initialized identity, SQL reservation only, and bounded async `BEGIN IMMEDIATE` retries; callback failures are never treated as lock contention. Preserve the lock DB and sidecars during test reset.
- Freeze `readLedgerSnapshot(rootDir, { maxBytes = 64 * 1024 * 1024, maxAttempts = 3 })`: positive safe-integer limits; discriminated `status: complete | incomplete_tail | in_progress`, `records`, `byteLength`, `completeBytes`, `lastSequence`, and optional `pendingRecord`. Stable complete/incomplete results contain only validated newline-terminated records; a valid unterminated JSON record is `pendingRecord`, never silently lost. Exhausted retries return `in_progress` with no records and null byte/sequence metadata. `LedgerReadError.code` is `ledger_corruption`, `unsupported_schema`, `snapshot_limit`, or `incomplete_snapshot`, with bounded offset/sequence diagnostics and no raw payload. Visibility is not proof of an acknowledged/fsynced writer commit. Existing array/replay APIs require `complete` and otherwise throw. Capture fd size and verify unchanged fd/path/manifest metadata; readonly reads never repair. Compaction atomically replaces a synced temporary ledger rather than rewriting a reader's inode.
- Recover sequence allocation from the maximum of validated ledger sequence and durable historical high-water. Before compaction removes any high sequence, persist its high-water. Reject duplicate IDs/non-increasing sequences, unsupported record/manifest versions, and unsafe integers. Corruption never becomes empty state. Complete JSON that fails schema validation is preserved even without a newline. Only a demonstrably truncated final JSON/UTF-8 boundary may be repaired under exclusive ownership. First persist the exact rejected bytes in `.recovery/<random-id>.tail` (directory 0700, files 0600), fsync the evidence and its directory, durably publish newly created parent entries by syncing the state root and every newly created ancestor (also for `locks/`), then truncate and fsync the ledger. Never export recovery bytes or references. Valid unterminated records are finalized with a synced newline. Crash tests cover evidence write/sync/truncate ordering. A missing manifest with existing records cannot authorize allocation that forgets historical compaction high-water.
- Retention selection and dependency closure run inside one locked compaction snapshot. Active sessions, pending approvals, live worktree leases and their cross-kind references preserve required history; kept turns/events retain ancestor sessions, approval responses retain requests, and referenced entities retain their dependencies. Expired terminal history can be pruned without resurrecting older active states. Reopen/append never reuses a sequence. Replay derives each output from one snapshot using ledger sequence and explicit session/task/entity keys.
- Add `readOnly` to store/ledger open options; readonly open, `getManifest`, list/query and CLI session inspection never create directories, repair tails, migrate manifests, or acquire writer locks. Route-task dry-run consumes readonly ledger state; coordination-specific arbitration/effect semantics remain COORD's work.
- Measure before optimizing. A validated in-memory append cache may be reused only while device/inode/size/mtime/ctime match under the writer lock; foreign writes invalidate it. Indexes are rebuildable checkpoints rather than record authority, and append may defer index rebuilding with documented cache staleness. Measure work counts and latency on the same growing fixtures and competing-process topology; document fsync latency tradeoffs rather than impose a fragile speed threshold.
- Preserve current public unknown-field stripping/passthrough behavior; recursively scan retained metadata and redacted tool/coordination bodies. Do not reject discarded extensions or apply blanket strictness. `sendTurnRequestSchema.message` continues accepting empty, whitespace, ordinary and long multibyte strings; missing/non-string values reject. Authorized runtime content stays usable while metadata-only persistence/export uses explicit projections. Freeze CLI export paths as opaque `path:sha256:<digest>` strings while retaining absolute operational roots internally; apply projection to envelope constructors, direct JSON/text rendering, health, session and UI outputs. No CLI argv changes (COORD owns them).
- Freeze a lease-release projection without adding a public ledger kind: a `worktree_lease` record retains the same lease ID/fencing token and sets `renewedAt` and `expiresAt` to the release timestamp, with optional backward-compatible `release: { cause: holder_release | reconciliation | recovery, actor: bounded metadata string, releasedAt: timestamp }`. The constructor requires provenance; old records without provenance remain unknown, never inferred holder releases. Export a shared release constructor in `worktree.ts`; replay/retention select the latest ledger sequence, so older active renewals cannot resurrect a released lease. Existing metadata-safe v0.1 leases without release attribution remain parseable; this additive release compatibility does not exempt historical raw-content records from the stricter metadata policy. Complete content-invalid records fail with bounded corruption diagnostics and remain byte-for-byte intact; no automatic content migration or deletion is authorized. Actual release emission and fencing authority remain COORD-owned. Local and Supabase coordination send/list boundaries validate retained metadata bodies using the shared corpus before persistence or RPC export.

Implementation review clarifications: operational paths allow home workspaces but still reject credentials and private recovery references. Sensitive-field containers and header-style names use the same corpus as strings, with validated redacted-config placeholders allowed. Scoped identifiers use collision-free tuple keys. Retained terminal metadata keeps latest ancestor records without protecting all expired descendant history; active/pending/live roots retain their required history. Directory initialization syncs every writable ancestor even when another initializer won creation, stopping before the first ancestor this user cannot modify; pre-existing execute-only workspace parents need not be opened. Terminal and tool runtime bodies are explicitly projected before audit persistence. Public runtime tool bodies retain their existing unknown-value compatibility; the metadata scanner applies at durable construction/export boundaries. These refinements preserve the frozen DATA acceptance intent and must pass renewed panel and independent review.

Integration-test ownership amendment: SL-1 also owns `packages/omnigent-transport/src/event-mapper.test.ts` and `packages/omnigent-transport/src/history-mapper.test.ts` solely to prove normal home-path/code tool traffic remains usable through the existing live/history mappers. Production transport mapping and public redaction labels remain WIRE-owned. SL-0 adds a real execute-only, non-writable ancestor regression for the writable-ancestor sync boundary.

Serialization-boundary repair: retained metadata must be inert JSON data. Direct durable schemas reject functions, accessors, proxies, custom prototypes and callable serialization hooks, including non-enumerable and array hooks. Export/audit projection replaces those unsupported values without invoking them; public runtime tool bodies remain unrestricted unknown values. Bound payload size only after durable schema validation, so serialization cannot run unvalidated hooks. Renewed reviews must verify both direct-write rejection and projected persistence with hook invocation counters.

Further acceptance repairs: evidence byte bounds include untrimmed input; recovery references in keys and encoded scalar strings reject. Private ledger append/read normalization derives omitted scope from kind-specific payload IDs and rejects conflicting duplicate scope, without changing public schemas or inferring response/evidence context. Retained requests keep their latest resolution. Compaction validates both checkpoints and serialized kept records, and pending-record finalization checks its added newline byte, before acknowledging growth. Future manifest version/literal combinations classify as unsupported schemas. Renewed review must verify these cases against EC-DATA-1..4.

Reference: [SQLite's POSIX lock/close constraint](https://www.sqlite.org/howtocorrupt.html#posix_advisory_locks_canceled_by_a_separate_thread_doing_close). Review this material amendment before implementation. Agent-harness panel CR and separate independent review must pass before merge; manual tool-enabled Opus 5.5/Gemini legs and Sol instead of Grok remain the owner's requested review routes.
