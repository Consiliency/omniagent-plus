# Proposal: reuse Omnigent sandbox primitives behind harness placement

Status: proposed; no architecture amendment, implementation approval, dependency upgrade, deployment or phase acceptance. This document prepares an owner decision. The [continuation handoff](continuation-handoff-20261011.md) and its [sandbox](evidence/research/harness-sandbox-assessment-20261011.json) and [T3](evidence/research/T3-base-assessment-20261011.json) research records remain intact. Fresh observations and review readiness belong in [the continuation record](evidence/research/sandbox-reuse-continuation-20261011.json).

## Recommendation and bounded scope

Keep the approved harness sequence: self-hosted SSH qualification, reconnect, placed Claude, then Codex and Grok under leased subordinate uids. Cloud follows those plans; the self-hosted HTTPS service (Plan 3) remains unchanged, after SSH. Placement coverage and review membership are separate: preserve the owner's Sol review roster rather than restoring Grok automatically.

Reuse provider lifecycle/transport primitives through one narrow adapter behind `sandbox_placement.ExecutingBackend`. Map **Omnigent's E2B `SandboxLauncher` / `SandboxExecTransport`** as the concrete cloud follow-on candidate; do not make E2B, OpenShell, a managed Omnigent session, or a T3 bridge the first SSH control plane. Omnigent has no demonstrated generic, conformant harness SSH backend. The first SSH backend remains the existing harness follow-on's responsibility. Its guest can evaluate upstream confinement/proxy primitives, but replacing the qualified seat profile is a separate reviewed amendment.

The immediate deliverable is this contract mapping, gaps and qualification design. The proposed first executable slice is one self-hosted SSH backend with a credential-free qualification workload, leaving `_NONLOCAL_EXECUTION_DRIVER=False`. Reconnect and the first real placed subscription Claude review leg remain separately reviewed follow-ons. The E2B mapping identifies reusable work for the already-sequenced cloud plan; implementing it now would change sequencing and is not recommended.

No T3 adapter, new runtime IDs, fleet daemon, license choice, shared adapter package, managed host registration, dependency addition or roadmap rewrite belongs to this slice. The dual-runtime architecture and shared optional package in the research remain recommendations. Keep execution and provider history with one execution owner; coordinator projections retain policy/evidence rather than a second execution log.

## Responsibility and contract mapping

Harness owns admission, review-isolation authorization and both stage revalidations; source/destination identity; the placement ladder, journal and runtime receipts; bounded calls; qualification and real seat launches; board/president semantics. Omnigent owns its configured provider plumbing and reusable transport/lifecycle mechanisms. Its managed-session reaper is not the harness lease authority.

Omniagent-plus retains routing, identity, provider-family cooldowns and its fleet holder/fence/expiry store. A fleet lease and a harness placement lease remain distinct. A future composition must recheck fleet ownership in the seal guard immediately before dispatch and stop owned work on loss; preflight alone is too early. Ownership never derives from an inbox, provider TTL or placement receipt. This is INTEG work, not delivered here.

The mapping uses Omnigent `onboarding/sandboxes/{base,types,registry,e2b}.py` and harness placement contracts/C1–C12. The cloud baseline is **`plans/detailed-e2b-cloud-backend-896-20260929.md`, as amended October 10**, under [agent-harness#1165](https://github.com/Consiliency/agent-harness/issues/1165): 4a1 control plane, 4a2 image/guest/upload, 4b placed seat. It plans direct SDK use in harness `sandbox_e2b.py`, optional `e2b>=2.51,<3`. Its SDK research records metadata, bounded lifetime, paginated listing and stdin support; the gaps below concern **Omnigent's launcher**, not an assertion that E2B's SDK lacks those features. That SDK research has not been independently requalified here.

## Authorization and evidence boundaries

Use current v11 **EC-HARDEN-6**: “a review seat holds only the capability its seat profile declares, a board path runs only with a valid review-isolation authorization, and any deliberately credentialed or tooled seat is recorded on the verdict; falsified by an undeclared capability or an unauthorized board path.” EC-HARDEN-5 is retired. SBXEXEC/SBXFETCH/SBXSEAT remains proposal-only.

Preserve C5's empty private allowlist and explicit required capabilities. Backend verification methods are claims unless independently measured. Signed destination attestation is **deferred, not dropped; required before any gate relies on a far end's claims and before the cloud backend**. Until then claims remain unsigned and no gate reads them. Provider booleans or unsigned null-workload results cannot establish accepted confinement.

Only expiring subscription access credentials may travel for a placed review; renewal credentials stay on the launcher. Recheck the lifetime floor immediately before sealing. No secrets, raw transcripts/provider payloads or environment values enter metadata evidence. Keep profile, authorization/source/request digests, opaque owner/lease/ref identifiers, capability names and provenance, bounds, status/truncation, cleanup confirmation and unresolved obligations. A real review's text is handled separately under its authorized review policy.

## One qualification, followed by a real required leg

Use the same production driver and packaged worker for these stages; do not substitute a bespoke smoke launcher.

1. **SSH qualification, flag off:** prepare a harmless synthetic stage through runtime staging; revalidate authorization/stage at the existing boundaries; reserve one owner/lease; transfer and recompute the exact manifest at destination. The owned credential-free workload reads a known marker and returns bounded, digest-bound output. Require qualification receipts and `sandbox_root_applied=false`.
2. **Fault qualification:** corrupt stage and reject before launch; test cancellation, overflow, hung calls and wrong owner/ref/digest. Crash before admission: no remote effect without the durable journal. Crash after allocation/before returned-ref persistence: recover by owner/lease, fence, discover and destroy. Renew without moving the end; prove the guest ends at `must_end_within_s` with the launcher dead/disconnected. Cancel, kill and confirm absence across pages. Kill an unknown lease, then deliver delayed admit/commit/execute: refuse all, remove late resources, execute nothing. Unconfirmed destruction retains the fenced journal for reaping; no retry/rung switch after uncertain launch.
3. **Reconnect follow-on:** implement the approved limited survival and same-run reconnect contract, then rerun qualification for lost connection and fixed-end/owner-loss cases. This amends `wait`/`run_placed`; it is not delivered by upstream `attach` or `resume`.
4. **Placed-Claude follow-on:** qualify the board's actual jailed Opus 5.5 subscription TUI seat through `place`/`run_placed`, with tools, exact source reading and a usable known verdict on the same driver/worker/backend. Verify first-party identity, build equality, grounding, fresh authorization, narrowed credentials and recorded profile; zero local provider spawns. Only its reviewed plan may enable the flag. Null workload, SDK-Claude or a manually launched local TUI cannot satisfy this acceptance.

The SSH plan supplies the conformance suite and `phase-loop placement qualify`; reuse driver/lease/placement/ladder tests and add backend controls. No live qualification ran here. The signature follow-on precedes the cloud backend's plan and any real-provider qualification that reads far-end claims. Cloud must pass shared conformance plus its own real provider path; SSH success never qualifies E2B. Preserve 4a1's tree-free control-plane scope, distinct from SSH stage qualification.

Gemini is separate: replay actual agy inference traffic against Omnigent's TLS proxy, checking trust/certificate handling, methods/paths, hostile alternate hosts, private addresses and direct-egress bypass. Shared Google front-end IPs cannot prove endpoint isolation. Until agent-harness#1170's profile is qualified, Gemini stays on its recorded local route; no tooled jail parity claim. Linux helper seccomp blocks new namespaces; it does not solve nested Codex. Windows Job Objects do not prove filesystem/network confinement.
