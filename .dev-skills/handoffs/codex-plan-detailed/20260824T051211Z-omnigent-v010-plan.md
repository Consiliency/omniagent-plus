# Handoff: Omnigent v0.10.0 accommodation plan

## Outcome

Created an execution-ready detailed plan for official Omnigent v0.10.0. The
bounded change refreshes tagged authority evidence, adds one optional
child-summary field and validation, proves structured errors remain lossless,
updates operator/security/coordination documentation, and prepares only
`@consiliency/omnigent-transport@0.6.0`. Implementation, review, merge, and
publication remain separate later gates.

## Load-bearing decisions

- Freeze only stable v0.10.0. Stop and amend if a newer stable release appears
  before implementation.
- Keep the exact 52-event array in `types.ts:68-121`; do not add v0.11-only
  `session.permission_mode` or `session.title`.
- Preserve existing lossless identity-free text and identity/cursor-based replay
  handling. v0.10 changes no output-delta wire shape.
- Add and validate only nullable `ChildSessionSummary.task_summary` in the
  transport-consumed response surface.
- Preserve structured HTTP errors losslessly in `OmnigentHttpError.body`; limit
  classification to canonical machine fields so title/cause/remediation cannot
  alter retry, auth/billing, policy, approval, or authority outcomes.
- Keep `omnigent server --background` as the production command. New start/host
  commands are operator surfaces only.
- Record bundle-root isolation as stable upstream v0.10 behavior, while making
  clear the transport does not implement that enforcement.
- Record upstream shared-editor approval rollback as non-authoritative for
  Consiliency leases, locks, routing, approvals, and authority.
- Keep v0.9 fixtures/loaders as historical regression evidence and add separate
  v0.10 evidence.
- Bump only the transport package to 0.6.0. Leave sibling versions and the npm
  OIDC workflow unchanged.
