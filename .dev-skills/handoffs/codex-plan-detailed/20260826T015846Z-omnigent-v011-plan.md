# Handoff: Omnigent v0.11.0 accommodation plan

## Outcome

Created and reconciled an execution-ready detailed plan for official Omnigent
v0.11.0. The bounded change adds two metadata-only session event literals,
accepts the official identity-free pre-allocation failure shape, preserves
background-task detail without granting lifecycle authority, refreshes tagged
evidence, and keeps the already prepared but unpublished transport version at
0.6.0.

Implementation may proceed in an isolated worktree and open an exact-head
reviewed PR. Merge and npm publication remain later explicit gates.

## Frozen authority

- Official release: v0.11.0, published 2026-08-25
- Tag commit: 496b7b13f6af3ed5330b957df408fc91290b6307
- PyPI: omnigent 0.11.0, Python >=3.12
- Direct v0.10-to-v0.11 delta: 100 operations, 72 paths, 143 schemas, four
  schema additions, eight changed schemas, no path/schema removals
- Stable stream union: 54 events, adding only session.permission_mode and
  session.title
- Published transport baseline: @consiliency/omnigent-transport@0.5.0
- Planned transport release: retain unpublished 0.6.0

## Load-bearing decisions

- Stop before authority edits if latest stable is not v0.11.0, the tag SHA or
  PyPI/OpenAPI contract differs, npm latest is not 0.5.0, or npm 0.6.0 exists.
- Accept id-less response.failed only with nested status exactly failed; reuse
  synthetic event identity and conservative existing turn correlation.
- Never invent an upstream response ID or attribute an ambiguous terminal to a
  turn.
- Accept permission/title events as raw metadata only. They emit zero neutral
  runtime events and grant no permission, approval, lease, lock, route, or
  policy authority.
- Preserve background-task detail best-effort on HTTP and SSE paths; malformed
  decorative detail cannot make a snapshot unusable or suppress lifecycle.
- Keep the existing internal untyped patch passthrough unchanged and add no
  typed or public permission/title/TUI control API.
- Preserve v0.9/v0.10 fixtures and loaders as historical evidence.
- Amend the single unpublished 0.6.0 changelog entry; do not bump sibling
  packages or change the publish workflow.
- Use NPM_PUBLISH_DRY_RUN=1 for publication proof. A trailing --dry-run is
  unsafe because the helper ignores it.
- Do not merge or publish at the implementation gate.
